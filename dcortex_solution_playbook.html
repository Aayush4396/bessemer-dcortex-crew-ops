Building the Agentic Crew Ops Advisor: The Path to 100/100

Airlines operate on paper-perfect plans that unravel every single day at 5:00 AM. When sick calls, duty-hour limits, lapsed medicals, or runway closures hit, the Crew Control desk must solve a recursive, multi-constraint puzzle across rosters, duty clocks, and a dense regulatory rulebook.

The Central Engineering Trap (Stated in Official Brief)

"The obvious approach — putting the dataset in the prompt and letting an LLM answer — works for Tier 1 and fails completely at Tier 2 and Tier 3." Legality is exact arithmetic; an LLM that approximates a duty hour or sector calculation produces answers that are fluent, confident, and illegal. Operationally, that is worse than no answer.

The 3-Tier Ladder: Where Hackathons Are Won

The challenge tiers are structured so every team has an on-ramp, and no team hits a ceiling.

Target: Polished T1 + Rigorous T2 + Ranked T3
Tier 1: Mandatory Lookup & Retrieval

Direct Operational Facts

Directly answerable from the relational data with zero domain modeling required.

"Who's on reserve at BLR tomorrow?"
"How many duty hours does C-1042 have left this week?"
"List crew whose licence expires in 30 days."
✓ Solved by: Text-to-SQL / SQLite indexed tables
Tier 2: Expected Consequence & Simulation

Impact & Ripple Analysis

Requires reasoning about consequences: tracing broken pairings, downstream flights, and secondary duty breaches.

"Captain C-1042 called in sick for tomorrow — which flights are now uncrewed?"
"If I move FO C-2087 onto DX412, does anyone breach a duty limit?"
"Station BLR is closed 14:00-20:00 — what's the crew impact?"
✓ Solved by: Pairing Graph Tracer + Exact Rule Checkers
Tier 3: Stretch (Winning) Action & Ranking

Ranked Legal Solutions

Synthesizing viable recovery options, verifying them against all 7 rules, computing cost in INR, and ranking trade-offs.

"Captain C-1042 is out — what should I do?"
Outputs: Ranked candidate actions with exact INR cost, rules checked, coverage, and reasoning trail.
Bonus: Draft crew notifications via SMS/voice.
✓ Solved by: Deterministic Combinatorial Pruner + Cost Function
Where the Boundary Must Be Drawn: What Code Does vs. What AI Does
Deterministic Python / SQL Engine (The Truth Layer)
  • Exact Duty Clock Math: Calculating remaining hours against the 60h/7d and 100h/28d ceilings.
  • FDP Table Verification: Exact sector reductions (13h down to 9h).
  • Pairing Traversal: Finding all flight legs tied to pairing P-2291.
  • Financial Calculations: Multiplying callout, deadhead ticket, and penalty rates in INR.
  • Zero Tolerance: 100% pass/fail decisions on regulations.
Large Language Model (The Reasoning & Narrative Layer)
  • Intent & Entity Parsing: Extracting crew ID (C-1042), date, flight number from natural English.
  • Tool Selection: Calling the appropriate Python function with extracted arguments.
  • Hypothesis Generation: Proposing candidate solutions (e.g. reserve activation vs deadhead from DEL).
  • Human-Readable Explanations: Synthesizing plain-language rationales why Option 1 beats Option 2.
  • Notification Drafting: Generating professional ACARS/WhatsApp messages to notify crew.

The 7-Step Hackathon Implementation Roadmap

Structured chronological sequence to build from data ingestion to winning live demo.

STEP 1 (Hours 0 - 2) Data Modeling

Ingest Synthetic JSON Files into In-Memory SQLite

The starter pack contains 11 relational JSON files. Instead of performing expensive semantic vector searches or raw text dumps into prompts, load all tables into a fast local SQLite database with relational foreign keys.

sqlite3.connect(':memory:') → load flights, crew, rosters, duty_clocks, reserve_pool, certifications
STEP 2 (Hours 2 - 5) Deterministic Core

Build the 7 Hard Rule Validators in Pure Python

Implement exact arithmetic functions for RULE-FDP-01 through RULE-BASE-07. Write unit tests using the 6 worked scenarios in scenarios.json to prove 100% agreement with the official answer keys.

def check_legality(crew_id, proposed_duty) -> {"is_legal": bool, "violated_rules": list}
STEP 3 (Hours 5 - 8) Tier 1 Engine

Build the Tier 1 Natural Language Query Engine

Implement an intent-routing mechanism (using LangChain, function calling, or regularized few-shot prompts) that maps questions like "Who's on reserve at BLR tomorrow?" into precise SQL queries.

User Query → LLM Tool Call (e.g. query_reserve_pool(base="BLR", date="2026-09-15")) → SQLite Result
STEP 4 (Hours 8 - 12) Tier 2 Simulation

Build the Consequence & Ripple Tracer

When crew calls sick, trace their assigned pairing (e.g. P-2291). Extract all subsequent legs (e.g. DX412, DX413, DX588), sum passengers affected, and evaluate secondary downstream crew assignment conflicts.

trace_consequences(sick_crew_id="C-1042", date="2026-09-15") → exact JSON matching Page 4 schema
STEP 5 (Hours 12 - 16) Tier 3 Solver

Build Heuristic Candidate Generation & INR Cost Scoring

Generate 3 candidate tactics: (1) Local Reserve Standby, (2) Inbound Crew Swap, (3) Deadheading from alternate base. Filter out illegal candidates with the Step 2 rule validator, calculate exact cost in INR using costs.json, and sort ascending by cost.

STEP 6 (Hours 16 - 19) Explainability & UX

Generate Controller Reasoning Trails & Crew Notification Messages

Format the output with visible explanations of why options were selected and rejected. Draft ready-to-send SMS/WhatsApp alerts for the replacement crew (bonus feature).

STEP 7 (Hours 19 - 24) Verification & Demo Prep

Run Dataset Validator, Benchmark Against Questions, & Rehearse Demo

Run validate.py to confirm relational integrity. Test against all ~40 questions in questions.json. Prepare the mandatory architecture diagram, README, and honest failure analysis.

The 7 Hard Legality Rules (Exact Arithmetic Engine)

        
Official machine-readable constraints from `rules.json` that the advisor must never hallucinate on.

      


      

        
        

          

            RULE-FDP-01
            Duty Period
          

          
Flight Duty Period (FDP) Limit

          

            Maximum FDP of 13.0 hours, progressively reduced by sectors flown (1-2 sectors: 13h, 3 sectors: 12h, 4 sectors: 11h, 5+ sectors: 10h).
          

        


        
        

          

            RULE-DUTY-02
            7-Day Cumulative
          

          
60 Duty Hours in 7 Days

          

            Maximum of 60 duty hours in any 7 consecutive days. Exceeding by even 1 minute grounds the pilot.
          

        


        
        

          

            RULE-FLT-03
            28-Day Cumulative
          

          
100 Flight Hours in 28 Days

          

            Maximum 100 airborne flight hours (block hours) in any 28 consecutive days.
          

        


        
        

          

            RULE-REST-04
            Mandatory Rest
          

          
Minimum 12h Rest Window

          

            Minimum 12 uninterrupted hours of rest required prior to commencing any flight duty period.
          

        


        
        

          

            RULE-QUAL-05
            Type Rating
          

          
Aircraft Type Certification

          

            Crew must hold valid rating for assigned aircraft (e.g., A320 Captain cannot be assigned to B737 flight).
          

        


        
        

          

            RULE-CERT-06
            Active Validity
          

          
Certifications & Medicals

          

            All pilot licences, class-1 medicals, and recurrent training certificates must be strictly valid on duty date.
          

        


        
        

          

            RULE-BASE-07
            Station Geometry & Deadhead
          

          
Reserve Base Callout & Deadhead Penalty

          

            Reserve callouts must originate from the flight's departure station base (e.g. BLR for BLR departures), unless a repositioning commercial deadhead cost (plus flight delay buffer) is applied from an alternate hub (e.g. DEL).

          1. dataset_loader.py — SQLite Ingestion & Relational Storage
          
        

        
import json
import sqlite3
from pathlib import Path

def init_airline_database(data_dir: str = "./data") -> sqlite3.Connection:
    conn = sqlite3.connect(":memory:")
    cur = conn.cursor()
    
    # 1. Crew table
    cur.execute("""
        CREATE TABLE crew (
            crew_id TEXT PRIMARY KEY,
            name TEXT,
            rank TEXT,
            base TEXT,
            ratings TEXT,
            seniority INTEGER,
            reachability_minutes INTEGER
        )
    """)
    
    # 2. Duty clocks table
    cur.execute("""
        CREATE TABLE duty_clocks (
            crew_id TEXT PRIMARY KEY,
            duty_hours_7d REAL,
            flight_hours_28d REAL,
            last_rest_ended TEXT,
            FOREIGN KEY (crew_id) REFERENCES crew(crew_id)
        )
    """)
    
    # Ingest JSON files into SQLite
    p = Path(data_dir)
    with open(p / "crew.json") as f:
        for c in json.load(f):
            cur.execute("INSERT INTO crew VALUES (?, ?, ?, ?, ?, ?, ?)",
                        (c["crew_id"], c["name"], c["rank"], c["base"], json.dumps(c["ratings"]), c["seniority"], c["reachability_minutes"]))
            
    with open(p / "duty_clocks.json") as f:
        for d in json.load(f):
            cur.execute("INSERT INTO duty_clocks VALUES (?, ?, ?, ?)",
                        (d["crew_id"], d["duty_hours_7d"], d["flight_hours_28d"], d["last_rest_ended"]))
            
    conn.commit()
    return conn

      


      
      

        

          2. rules_engine.py — Deterministic 7-Rule Validator
          
        

        
from datetime import datetime, timedelta

def get_max_fdp_hours(num_sectors: int) -> float:
    """RULE-FDP-01: Max 13 hours, reduced by sectors."""
    table = {1: 13.0, 2: 13.0, 3: 12.0, 4: 11.0, 5: 10.0}
    return table.get(num_sectors, 9.0)

def validate_candidate(crew: dict, clock: dict, pairing_flights: list[dict], certs: dict, duty_date: str) -> dict:
    violated_rules = []
    rules_checked = ["RULE-FDP-01", "RULE-DUTY-02", "RULE-FLT-03", "RULE-REST-04", "RULE-QUAL-05", "RULE-CERT-06", "RULE-BASE-07"]
    
    # 1. RULE-QUAL-05: Rating match
    required_type = pairing_flights[0]["aircraft_type"]
    if required_type not in crew["ratings"]:
        violated_rules.append({"rule": "RULE-QUAL-05", "detail": f"Crew lacks {required_type} rating"})
        
    # 2. RULE-DUTY-02: 60h in 7 days
    new_duty_hours = sum(f["block_minutes"] / 60.0 for f in pairing_flights) + 1.0 # 60m pre-briefing
    if clock["duty_hours_7d"] + new_duty_hours > 60.0:
        excess = (clock["duty_hours_7d"] + new_duty_hours) - 60.0
        violated_rules.append({"rule": "RULE-DUTY-02", "detail": f"Exceeds 60h/7d limit by {excess:.1f} hours"})
        
    # 3. RULE-FDP-01: Max FDP by sector
    max_fdp = get_max_fdp_hours(len(pairing_flights))
    if new_duty_hours > max_fdp:
        violated_rules.append({"rule": "RULE-FDP-01", "detail": f"Duty of {new_duty_hours:.1f}h exceeds max FDP of {max_fdp}h"})
        
    is_legal = len(violated_rules) == 0
    return {
        "legal": is_legal,
        "rules_checked": rules_checked,
        "violations": violated_rules
    }

      


      
      

        

          3. consequence_tracer.py — Tier 2 Ripple Engine
          
        

        
def trace_disruption(conn, sick_crew_id: str, date: str) -> dict:
    cur = conn.cursor()
    
    # 1. Find broken pairing
    cur.execute("SELECT pairing_id, flight_numbers FROM rosters WHERE crew_id = ? AND date = ?", (sick_crew_id, date))
    row = cur.fetchone()
    if not row:
        return {"error": "Crew not assigned to any pairing on this date"}
        
    pairing_id, flights_json = row[0], row[1]
    flight_list = json.loads(flights_json)
    
    # 2. Count passengers affected
    pax_total = 0
    for f_num in flight_list:
        cur.execute("SELECT pax_count FROM flights WHERE flight_num = ?", (f_num,))
        pax_total += cur.fetchone()[0]
        
    return {
        "uncrewed_flights": flight_list,
        "pairing_broken": pairing_id,
        "passengers_affected": pax_total
    }
